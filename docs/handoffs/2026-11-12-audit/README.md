## 一页纸结论

1. **仓库 247 万行源码里，接到入口上的只有 6.4%。** 不可达的 231.5 万行有 95.9% 是 7 月 3 日到
   16 日两周内生成的，绝大多数是报告、摘要、评分类模块；抽样所见，没有任何数据源喂给它们。
   测试代码的 73% 在保护这些不会运行的东西。
2. **你现在真正在推进的模拟盘，决策闭环不在仓库里。** 仓库只有模型数学和闸门规则；扫描、
   组候选、写账本、结算都在服务器的逐轮脚本里，评审和 CI 都覆盖不到。跨联赛胜负盘计划 11-24
   恢复，而它的两个强制检查点是否已接进服务器脚本，仓库里没有证据。
3. **现有盈亏数字偏乐观，也不足以证明有优势。** 仓库里唯一的账本快照（40 笔）回报率 +23.3%，
   95% 区间从 −13.9% 到 +60.8%，一个市场（两次入场）占了 51% 的盈亏，而且没有扣手续费
   （扣后约 +20.6%）。
   缺的不是更多的盈亏数据，而是"模型对市场"的基准和收盘价记录。
4. **官方蓝图只描述了一半的项目。** `DELIVERY_PLAN.md` 还写着唯一里程碑是 V1 的六个工作包；
   V1 自 10-10 起只差你的一个启动决定，之后源码没再动过；11 月的工作全在它的范围之外。
5. **模型研究的纪律是好的，要保留。** 影子验证、冻结阈值、独立复审、不达标不放行，这些都在
   起作用。优化方案是把同样的纪律扩展到证据链和工程链。
6. **没有发现会造成真实损失的问题。** "只做纸面"的边界真实成立，没有泄露的凭据。

## 优化方案的骨架

- **一条主线**：模拟盘策略，从纸面一步步走向小额真实盘；V1 的 LLM 研究作为备线冻结待决。
- **一条证据链**：每个候选（包括被拒绝的）连同模型版本、数据快照、订单簿、闸门结果、代码提交号
  入库；盈亏逐笔结算并扣费；记录收盘价。
- **一张状态表**：`DELIVERY_PLAN.md` 顶部一页，回答"几条线、各到哪、等谁"。
- **六个里程碑**：M0 口径与基线（约一周）→ M1 证据底座 → M2 闭环入库 → M4 统计验证；M3 瘦身
  与前面并行；M5 只写第 2、3 级的设计。
- **八件要你拍板的事**（蓝图第 9 节），每件都有推荐和保守的默认做法，不答复也不会卡住开工。

## 完整性清单

- `MANIFEST.json`：本目录每个文件的路径、字节数和 SHA-256。
- `MANIFEST.sha256`：`sha256sum` 格式的同一份清单，另外包含 `MANIFEST.json` 自己的校验值。只要
  核对这一个文件的校验值，就等于核对了整个交接包。
- 两个清单文件不收录自己，也不收录 `05-local-agent-prompt.md`——提示词要写明交付提交号，只能在
  交付提交之后再提交。
- 校验命令写在提示词第 3 节。它读的是 git 对象而不是工作区文件，所以不受换行符转换的影响。

## `evidence/` 里有什么

| 文件 | 内容 |
| --- | --- |
| `audit_static.py` | 导入图、可达性、函数复杂度、重复、异常处理习惯。只做语法解析，不导入也不执行仓库代码。用法：`python3 -I audit_static.py <仓库根目录> <输出.json>` |
| `build_metrics.py` | 把上一个脚本的输出和 git 里每个源文件的首次提交日期汇总成下面三个文件。用法和取日期的 git 命令写在脚本开头 |
| `metrics.json` | 基线上的汇总数字，含方法说明 |
| `reachable_modules.txt` | 基线上可达的 419 个模块 |
| `unreachable_modules.tsv` | 基线上不可达的 2,438 个模块：模块名、行数、创建日期、家族 |
| `test_split.py`、`test_split_output.txt` | 把测试文件按"测的是不是可达代码"分类，及其在基线上的输出。用法：`python3 -I test_split.py <仓库根目录> <audit_static 的输出.json>` |
| `init_reach.py`、`init_reach_output.txt` | 估算各入口在导入时会加载多少模块，及其在基线上的输出。用法：`python3 -I init_reach.py <仓库根目录>` |
| `ledger_stats.py`、`ledger_stats_output.txt` | 对一份账本导出重算统计量，及其对 10-30 快照的输出。用法：`python3 -I ledger_stats.py <账本.json>` |
| `ci_run_42966642867_summary.txt` | 基线 CI 的通过数、121 个跳过项的明细和警告摘要 |
| `github_api_facts.txt` | 从 GitHub 接口读到的事实：提交数、分支数、未关闭的 PR、分支保护的返回、各工作流的运行历史 |

这些脚本是审核证据，不是项目代码：没有任何模块导入它们。建议把它们复制到仓库检出之外的目录
运行，把仓库路径作为参数传入。
