## 3. 每个节点的统一流程

沿用 `AGENTS.md` 现行的推送策略：

1. **计划**：写清对应条目、要改的文件（必须落在本泳道的文件集合内）、验收标准。计划先交独立
   只读复审。
2. **实现**：只动本泳道的文件。需要改共享文件（见蓝图 8.3 的单写者表）时，把改动内容交给该文件
   的单写者。
3. **验证**：聚焦测试；全量离线验证 `.venv/bin/python scripts/verify_local.py --full`；
   `git diff --check`；编译检查；秘密扫描；`python -m polymarket_alpha_lab.papersim.cli selfcheck`
   须为 10/10 且原有输出不变。
4. **本地提交**：一个节点一个聚焦提交，工作区干净。
5. **复审**：新派的、没参与过的只读子代理，给出 `VERDICT: PASS` 或 `VERDICT: FAIL` 及发现。
   不通过就修，修完重新复审。
6. **推送**：复审通过后推送。推送后比较两个远端 `main` 的提交号（FX-23）。
7. **记录**：在计划记录（蓝图 8.1；默认是 `DELIVERY_PLAN.md` 的新小节，由协调者落笔）追加一条，
   格式固定为——本次节点与对应条目、固定提交号与实测结果（含首次失败和重跑）、剩余缺口、
   状态板是否变化、下一步或在等谁。
8. **完成判据**（蓝图 8.2）：新增模块要么可达，要么登记为影子；不可达模块数不净增。

推送策略里的 CodeGraph 同步一项，按 2026-09-12 的授权可以不做；做没做，如实记录。

## 8. M4：统计验证

M4 不是一组开发任务，而是一个按周重复的节奏，从 M2 切换那天开始计时。

### 8.1 每周做什么

1. 运行 `evaluate`，把每个队列的报告追加进计划记录，更新状态板上各队列的一行：入场数、
   结算数、净回报率、收盘价偏离均值及区间；OD-G 批准之后再加上晋级标准 A–F 各条的状态。
2. OD-G 批准之后：检查暂停规则；触发了就停该队列的新入场，记录原因。
3. 某队列 A–F 全部满足时，出一份晋级评审材料交给你。晋级到第 2 级是你的决定，不是代理的。

### 8.2 多久能有结论

- 能计入晋级标准 C、D 的只有账本 v2 上线之后的数据——历史上的入场没有随笔记录收盘价，也没有
  被拒候选。
- 按 10 月的频率，足球大小球大约每周 6 笔入场。攒够 50 笔入场、30 笔结算大约要 8 周；
  200 个候选会更早达到。
- 所以量最大的队列最早也要在 M2 切换后约两个月才有第一次晋级评审。其他队列更慢。
- 这段时间里工程上不需要大量投入，产能可以放在模型研究和 M5 的设计上。

### 8.3 验证期内继续做的模型研究

## 10. 备线 R 的两种走法

| | OD-A 选 ①（推荐）：停在"工程完成、未激活" | OD-A 选 ②：做一次真实运行 |
| --- | --- | --- |
| 要做的事 | 状态板写明"V1：工程完成，等待 owner 的启动决定；不再投入新工程"；`DELIVERY_PLAN.md` 第 4 节总表保持原样 | 按 `docs/handoffs/g2-first-real-run-runbook-draft.md` 执行；需要你提供凭据窗口和最终的启动指令 |
| 之后 | 在 M4 的 8.4 时点重新评估 | G2 关闭后，G3 到 G6 仍需各自的工程和等待真实事件到期；V1 与主线并行会分走产能 |
| 对主线的影响 | 无 | M1、M2 的泳道数要相应减少 |

无论哪种，V1 的 75 个可达模块和 24 个待激活模块都保留，不进归档。

## 11. 风险与应对

| 风险 | 应对 |
| --- | --- |
| 搬迁时发现服务器脚本和库的行为不一致 | M2 的影子并跑，逐条归因；不为对齐而放宽闸门 |
| 归档误删了有用的代码 | 先打标签；保留名单；每批比较删除前后的可达清单必须完全相同 |
| 改文档、工作流或新增数据库模块把 CI 弄红 | 清单第 0 节第 2、3、4 条：两处迁移计数、读文档的测试、三个守卫测试，动手前先查 |
| 数据源再次中断 | Understat 与 FotMob 双源；取数失败就停止该轮，不用旧数据硬算；快照登记保证事后知道当时用的是哪一份 |
| 样本积累太慢，想降标准 | 标准在 OD-G 里预先定死；多队列各自积累但不合并；慢就是慢 |
| 你的决定迟迟不来 | 每项都有保守默认；状态板列出哪些节点因此被挡住 |
| Polymarket 调整费率 | 费率表带日期；市场元数据里的费率与表不一致时拒绝候选并报警 |
| 两个仓库走偏 | 每次推送后比较提交号；不一致立即停 |
| CI 分钟数耗尽 | 数据库通道只在相关推送和每周定时触发 |
| 11-24 的期限赶不上 | 默认就是保持冻结，赶不上不会出错，只是晚恢复 |

## 12. 汇报方式

每个节点完成后的汇报沿用 `DELIVERY_PLAN.md` 第 8 节规定的格式，一段话说清五件事：

**本次做了哪个节点、对应哪个条目 → 固定提交号和实测结果 → 这个里程碑还差什么 → 状态板有没有
变 → 下一步是什么、是否在等你。**

没有需要你做的事，就不派任务给你。需要你决定的事，一次说完，附推荐和默认。
