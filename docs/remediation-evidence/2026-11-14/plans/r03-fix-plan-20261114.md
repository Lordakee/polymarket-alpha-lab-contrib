## 设计（全部位于该测试文件内）

1. **seed 前等待 helper（父进程）** `_wait_for_seed_port_ready(rig, *, budget_s=90.0, interval_s=1.0, _clock=None, _sleep=None)`：
   - 就绪条件：`/proc/net/tcp` 与 `/proc/net/tcp6` 均可解析且任务端口 local TIME_WAIT 计数均为 0（复用 `_old_seed_tcp_counts` 语义：读 ≤65537B、>65536/无结尾换行/畸形 → `'UNAVAILABLE'`；只统计该端口的 local 侧，peer 侧仅入快照）。
   - 时序（DECISION 4）：进入即读一次并打印 `OLD_SEED_WAIT_BEFORE port=<P> tcp=<json|UNAVAILABLE> tcp6=<…> monotonic_ns=<…>`；两文件 local TW 均为 0 → 立即打印 `OLD_SEED_WAIT_AFTER … elapsed_s=<x>` 并返回（不睡）；非零 → 以 `time.sleep(1)` 轮询，累计单调时钟上限 90s（`time.monotonic` 自等待起点，不滚动续期），任一次轮询达到清空 → 打印 AFTER（含 elapsed）返回，随后原样执行一次 seed。
   - 失败路径：超时 → `pytest.fail`，消息含终态计数、实际耗时、原因"local TIME_WAIT did not clear within 90s"与 BEFORE 快照；任一次读取/解析 `'UNAVAILABLE'` → 立即 `pytest.fail`（UNKNOWN 绝不视为零），消息含不可判定文件、终态、耗时。两条路径都发生在 seed 启动前，首次失败与其后全部诊断保留。
   - 时钟/睡眠默认 `time.monotonic`/`time.sleep`，可注入假时钟仅供离线合成测试；生产行为即 1s/90s。
   - 插入点：`initialize_and_seed_with_old_source` 中 `status stopped` 断言之后、`_old_payload('seed.py', …)` 之前，仅一次调用。
2. **失败断言前逐字回显子进程 stderr（DECISION 1-C；复审 P2-1 修订）**：新增小 helper `_echo_seed_child_stderr(result)`——当 `result.returncode != 0` 或 stderr 缺 `PAYLOAD_SOURCE_OK` 时，父进程 `print('OLD_SEED_CHILD_STDERR_BEGIN')`、逐字 `print(_stderr_text(result))`、`print('OLD_SEED_CHILD_STDERR_END')`（绕过 pytest 对断言表达式的截断），随后原断言照常执行并失败；成功路径零输出。**调用点在 `_old_payload` 内部 `seed.py` 失败分支**：与 `_observe_old_seed_exit` 同层、置于其前、且在函数末尾 provenance `assert` 之前——外层 `initialize_and_seed_with_old_source` 的调用点在缺-marker 主失败场景下到不了控制流（provenance assert 先抛），故不做外层调用。合成测试除直接调 helper 外，**必须补一个经真实 `_old_payload` 包装层的集成用例**钉住该路径：monkeypatch 模块级 `_run`/`_payload_file` 返回缺-marker 的失败 CompletedProcess，`pytest.raises(AssertionError)` 捕获 provenance assert，capsys 断言 BEGIN/END 之间逐字等于子进程 stderr——证明回显先于断言触发。回显安全性（P3-3）：回显内容与既有 `_stderr_text(result)` 断言消息同源（同一子进程 stderr、同为测试自身合成/诊断输出），仅提前打印，不扩大暴露面，无凭据/地址新增。
